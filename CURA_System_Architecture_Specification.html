Executive Summary

1. Architectural Vision & System Principles

CURA is an adaptive, multi-modal cognitive assistant engineered to support neurodivergent individuals (ADHD) and memory-impaired seniors (Alzheimer's disease), alongside high-efficiency everyday voice automation. The system dynamically alters its personality, UI complexity, interaction pacing, and sensory output based on active cognitive profiles.

Key Architecture Directives for All Teams:
  • Official Naming Policy: The official name of the project is CURA and nothing else. Legacy references to JAS or JARVIS in historical drafts are superseded.
  • Edge AI Hardware Isolation: The machine learning pipeline (STT, LLM, TTS) is deployed directly on a Raspberry Pi 4 Model B (4GB RAM). The camera module is explicitly excluded to preserve 100% of CPU and RAM for sub-second voice and language inference.
  • Network Connectivity: The Raspberry Pi hardware operates connected via Wi-Fi 802.11ac to cloud services and local client GUIs over secure WebSockets and REST APIs.
  • Total Memory Envelope: The on-device memory consumption must not exceed 2.2 GB – 2.8 GB RAM under full load, leaving headroom for the OS and preventing Out-Of-Memory (OOM) fatal kills.

Core Software Engineering Principles Enforced Across All Teams

Principle Software Engineering Rule Application in CURA
S — Single Responsibility (SRP) A class, module, or service must have one and only one reason to change. Separate audio capture, transcription, prompt construction, tool execution, and voice synthesis into discrete decoupled classes.
O — Open/Closed (OCP) Software entities should be open for extension, but closed for modification. Add new cognitive modes or external tool-calls by creating new polymorphic strategy classes without touching core router code.
L — Liskov Substitution (LSP) Subtypes must be substitutable for their base types without altering correctness. All audio sinks (Speaker, Virtual Stream, Test Mock) implement IAudioOutput interchangeably.
I — Interface Segregation (ISP) Clients should never be forced to depend on interfaces they do not use. Desktop GUI subscribes to IStateObserver, ignoring raw audio processing interfaces.
D — Dependency Inversion (DIP) High-level modules must not depend on low-level modules. Both must depend on abstractions. AI Orchestrator injects ILLMEngine rather than depending concretely on llama.cpp or Ollama.
Clean Architecture Independent of frameworks, UI, databases, and external agencies. Domain entities and business use cases remain pure without framework imports.
Contract-First Development Define OpenAPI 3.1 & AsyncAPI specifications before writing implementation code. Ensures Mobile, GUI, Web, Backend, and Hardware teams work in parallel against mock servers.

2.3 Production Tool Calling Router Implementation

# src/core/use_cases/tool_calling_router.py
from typing import Dict, Any, Callable
import json

class ToolRouter:
    """Open/Closed Principle: Register tools without mutating the core loop."""
    def __init__(self):
        self._registry: Dict[str, Callable] = {}

    def register_tool(self, name: str, handler: Callable):
        self._registry[name] = handler

    async def execute(self, tool_name: str, arguments: Dict[str, Any]) -> str:
        if tool_name not in self._registry:
            return json.dumps({"error": f"Tool '{tool_name}' not registered."})
        try:
            result = await self._registry[tool_name](**arguments)
            return json.dumps({"status": "success", "data": result}, ensure_ascii=False)
        except Exception as e:
            return json.dumps({"status": "failure", "error": str(e)})

// features/medication/data/repositories/medication_repository_impl.dart
class MedicationRepositoryImpl implements IMedicationRepository {
  final MedicationRemoteDataSource remoteSource;
  final MedicationLocalDataSource localCache;
  final NetworkInfo networkInfo;

  MedicationRepositoryImpl({required this.remoteSource, required this.localCache, required this.networkInfo});

  @override
  Future<Either<Failure, void>> confirmDoseTaken(String doseId, String transcription) async {
    // Offline-first: write to local database immediately, queue background sync if offline
    await localCache.markDoseConfirmed(doseId);
    if (await networkInfo.isConnected) {
      return await remoteSource.sendDoseConfirmation(doseId, transcription);
    } else {
      await localCache.queuePendingSync(doseId);
      return const Right(null);
    }
  }
}

5.2 "Try CURA" Interactive Voice Demo Architecture (`FR-WEB-005`)

To let reviewers and visitors experience CURA directly from any modern browser without installing local models, the web demo implements Web Audio API capturing audio chunks and streaming them to the backend orchestrator: 

// components/modules/VoiceDemoRecorder.tsx
'use client';
import React, { useState, useRef } from 'react';

export const VoiceDemoRecorder: React.FC = () => {
  const [isRecording, setIsRecording] = useState(false);
  const [responseAudio, setResponseAudio] = useState<string | null>(null);
  const mediaRecorderRef = useRef<MediaRecorder | null>(null);

  const startVoiceSession = async () => {
    const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
    const mediaRecorder = new MediaRecorder(stream, { mimeType: 'audio/webm' });
    const audioChunks: Blob[] = [];

    mediaRecorder.ondataavailable = (event) => audioChunks.push(event.data);
    mediaRecorder.onstop = async () => {
      const audioBlob = new Blob(audioChunks, { type: 'audio/webm' });
      const formData = new FormData();
      formData.append('audio_file', audioBlob, 'voice_input.webm');
      
      const response = await fetch('/api/v1/voice/demo-interact', {
        method: 'POST',
        body: formData,
      });
      const result = await response.json();
      setResponseAudio(result.audio_url);
    };

    mediaRecorder.start();
    setIsRecording(true);
    mediaRecorderRef.current = mediaRecorder;
  };

  return (
    <div className="cura-recorder-card">
      <button onClick={isRecording ? () => mediaRecorderRef.current?.stop() : startVoiceSession}>
        {isRecording ? "Listening... (Click to Stop)" : "Speak to CURA"}
      </button>
    </div>
  );
};

6.3 Hardware Daemon & Debounced Interrupt Handler

# hardware/daemon/emergency_listener.py
import RPi.GPIO as GPIO
import time
import asyncio
import aiohttp

BUTTON_PIN = 17
DEBOUNCE_MS = 250

class EmergencyTriggerDaemon:
    def __init__(self, api_endpoint: str):
        self.api_endpoint = api_endpoint
        self.last_press_time = 0
        GPIO.setmode(GPIO.BCM)
        GPIO.setup(BUTTON_PIN, GPIO.IN, pull_up_down=GPIO.PUD_UP)
        GPIO.add_event_detect(BUTTON_PIN, GPIO.FALLING, callback=self._handle_interrupt, bouncetime=DEBOUNCE_MS)

    def _handle_interrupt(self, channel):
        current_time = time.time() * 1000
        if current_time - self.last_press_time > DEBOUNCE_MS:
            self.last_press_time = current_time
            print("[HARDWARE INTERRUPT] Emergency Push Button Pressed!")
            asyncio.run(self._broadcast_emergency())

    async def _broadcast_emergency(self):
        async with aiohttp.ClientSession() as session:
            payload = {"source": "mini_cura_hardware_button", "timestamp": time.time()}
            await session.post(f"{self.api_endpoint}/api/v1/emergency/trigger", json=payload)
